# Design Language

## Purpose

This document defines the public-facing visual and language system for the Elyria AI Revalidation Engine.

The goal is premium enterprise presentation: executive-readable, technically credible, visually sharp, and public-safe.

---

## Visual Positioning

```text
Approval freshness
Lifecycle governance
Change-trigger review
Stale approval detection
Material-change control
Evidence-backed revalidation
```

---

## Palette

| Role | Color | Use |
|---|---|---|
| Deep graphite | `#1f4f5a` | Primary governance, approval boundary, executive surface |
| Signal teal | `#2f6f73` | ADMIT, valid approval, continuity |
| Muted steel | `#5f8fa3` | Evidence, lifecycle monitoring, platform operations |
| Warm gold | `#c9a66b` | HOLD, review, incomplete evidence, readiness gates |
| Refusal red | `#b94b4b` | REFUSE, critical boundary changed, stop continued use |
| Electric cyan | `#62d9ff` | Change detection, lifecycle signal, revalidation trigger flow |

## Voice

Use language that is:

- precise
- enterprise-readable
- governance-forward
- architecture-oriented
- operational
- public-safe
- confident without overclaiming

Correct public claim:

```text
public-safe enterprise reference architecture and deployable pilot sandbox
```

Avoid claiming this repository is a complete production enforcement system by itself.

---

## Core Phrases

```text
AI approval is not permanent.
Was approved does not mean is still approved.
Detect stale AI approval before changed systems continue producing consequence.
ADMIT / HOLD / REFUSE / REVALIDATE.
Show the architecture. Protect the machinery.
```
